# 2026-08-22

## 音频播放错误修复（chat.js）
- 用户反馈：聊天室收到语音播放报错 `errCode:10001, INNERERRCODE:-11828, ERRMSG:无法打开`（iOS 上 `kAudioFile_InvalidFileError`，即文件不是有效音频）。
- 根因分析：
  1. `wx.downloadFile` 的 success 回调在网络层"完成"时即触发，**即使服务器返回 403/404/500 也走 success**；原 `doDownloadFile` 完全没校验 `res.statusCode`，把错误页当音频临时文件保存 → 解码失败 -11828。
  2. **真正触发 -11828 的是扩展名**：服务器 `liaotianshi.onrender.com` 返回的音频 Content-Type 不是 `audio/mpeg`，微信把临时文件存成 `http://tmp/xxx.bin`；`InnerAudioContext` 依赖扩展名判格式，`.bin` 无法解码 → 报 -11828 / 10001。用户日志坐实：`...3shvymXnwlraff6423310be80109e51b7a57c50f1c29.bin`。
  3. 下载得到的临时文件可能被系统清理/损坏，导致 `InnerAudioContext` 无法打开。
  4. 服务器为 `https://liaotianshi.onrender.com`（免费托管），存在冷启动超时、Content-Type 不确定等风险；下载未带任何鉴权 header（目前看接口也不要求 token）。
- 修复（pages/chat/chat.js）：
  1. `playDownloadedAudio(filePath, filename, fileUrl)` 新增 `fileUrl` 参数。
  2. **`.bin` 修复**：播放前检测 `filePath` 扩展名，若不是 `mp3/wav/aac/m4a/ogg`，用 `wx.getFileSystemManager().copyFileSync` 把临时文件**复制成带正确扩展名（按 filename 取，缺省 mp3）的副本**再播放；复制失败则回退 `fileUrl` 网络链接。
  3. `onError` 中若本地解码失败且存在 `fileUrl`，自动用网络链接重播一次（绕开损坏/失效临时文件），仍失败才弹窗。
  4. `onEnded`/`onError` 结束播放后**删除复制出的临时副本**，避免 `USER_DATA_PATH` 反复累积 `audio_*.mp3`。
  5. `doDownloadFile` 的 downloadFile success 增加 `res.statusCode !== 200` 校验，非 200 直接报错提示（不再把错误页当音频）。
  6. 调用点（doDownloadFile 内音频 actionSheet "播放音频"）已把 `fileUrl` 透传进 `playDownloadedAudio`。
- 注意（已废弃）：早一版曾用 `wx.getFileSystemManager().accessSync(filePath)` 校验临时文件，但 `http://tmp/` 是微信伪协议路径，`accessSync` 不适用反而会误报 `no such file` 并报错——已改为按扩展名复制方案，不再对 `http://tmp/` 做 accessSync。
- 验证建议：另一账号发语音，当前账号接收后点播放；若仍失败，看 Console 是否打印 "音频临时文件扩展名异常，已复制为可播放文件" / "本地音频不可用，直接使用网络链接播放" / "回退网络链接播放也失败"，据此判断是否服务器/鉴权问题（需查服务端 Content-Type 或给 downloadFile 加 header）。
- 注意：同一 `onError` 块在 `playAudio`(2238) 与 `playDownloadedAudio`(4183) 中重复存在，编辑时靠各自 onCanplay 日志前缀唯一区分（"音频可以播放，时长:" vs "音频准备就绪，duration:"）。
